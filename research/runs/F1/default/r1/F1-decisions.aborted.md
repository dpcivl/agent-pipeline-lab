# F1 설계서 해석 결정

설계서 `docs/features/F1.md` v1이 정하지 않은 부분에 대해 메인 세션이 내린 해석입니다.

| id | 시점 | 설계서 문장 | 결정 | 근거 |
|---|---|---|---|---|
| D-1 | 1단계 계획 | "UTC, ISO 8601 형식 (예: `2026-10-29T01:23:45Z`)" | `YYYY-MM-DDTHH:MM:SSZ`, 초 단위, 마이크로초 없음, `Z` 접미사 | 설계서 예시와 같은 형식. 테스트가 하나의 형식으로 검증할 수 있음 |
| D-2 | 1단계 계획 | "스킴이 `http` 또는 `https`가 아님" | 대소문자 무시 비교. `HTTPS://example.com`은 허용하고 받은 그대로 저장 | RFC 3986에서 스킴은 대소문자를 구분하지 않음. 정규화 금지 원칙에 따라 저장 값은 바꾸지 않음 |
| D-3 | 1단계 계획 | 검증 목록에 공백·제어 문자 언급 없음 | 공백(0x20)과 ASCII 제어 문자(0x00–0x1F, 0x7F)가 하나라도 있으면 422 | 정규화(공백 제거)는 금지이므로 고칠 수 없음. 그대로 저장하면 `Location` 헤더 주입이나 서버 오류가 생김. 유효한 URL에는 이 문자가 날것으로 들어가지 않음 |
| D-4 | 1단계 계획 | "`Location: <원래 URL>`" | 저장한 URL을 그대로 `Location`에 넣음. 비ASCII 문자만 UTF-8 퍼센트 인코딩. Starlette `RedirectResponse`는 쓰지 않음 | `RedirectResponse`는 `\|`, `{` 등을 다시 인코딩해 글자가 달라짐. HTTP 헤더 값은 latin-1만 담을 수 있어 비ASCII는 인코딩이 불가피함 |
| D-5 | 1단계 계획 | 오류 응답 본문 형식 없음 | 422는 FastAPI 기본 검증 오류 본문, 404는 `{"detail": "Not Found"}` | 설계서는 상태 코드만 요구함 |
| D-6 | 1단계 계획 | "이미 있는 코드와 겹치면 다시 만듭니다" | `secrets` 모듈로 생성, PK 충돌 시 최대 10회 재시도, 넘으면 500 | 62^7 공간에서 10회 연속 충돌은 사실상 일어나지 않음. 무한 루프 방지 |
| D-7 | 1단계 계획 | "길이가 2,048자를 넘음" | 파이썬 문자열 길이(`len`, 코드 포인트 수) 기준 | 설계서가 "자"라고 표현함. 바이트 수가 아님 |
