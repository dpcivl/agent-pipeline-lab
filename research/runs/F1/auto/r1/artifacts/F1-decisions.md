# F1 설계서 해석 결정

auto 모드에서 메인 세션이 내린 해석과 근거를 기록한다.

## D-1. 스킴 대소문자

- 설계서: "스킴이 `http` 또는 `https`가 아님"
- 결정: 대소문자를 무시한다. `HTTPS://example.com`도 허용하고, 저장과 응답은 받은 그대로 한다.
- 근거: RFC 3986에서 스킴은 대소문자를 구분하지 않는다. 정규화 금지 규칙은 저장 값에만 적용된다.

## D-2. 공백과 제어 문자

- 설계서: 거절 조건 목록에 없음. "앞뒤 공백 제거 같은 정규화는 하지 않습니다."
- 결정: 스페이스와 제어 문자(U+0000–U+001F, U+007F)가 든 URL은 `422`로 거절한다.
- 근거: 정규화를 하지 않으므로 앞뒤 공백이 든 값을 고쳐 저장할 수 없다. 그대로 저장하면 `Location` 헤더에 공백이나 CR/LF가 들어가 잘못된 리다이렉트나 헤더 주입이 생길 수 있다. 올바른 URL에는 날 공백이 들어가지 않는다.

## D-3. 리다이렉트 `Location`의 비ASCII 문자

- 설계서: "`Location: <원래 URL>`"
- 결정: 출력 가능한 ASCII(U+0021–U+007E)는 `|`, `{`, `<`, `\` 같은 문자까지 모두 글자 그대로 내보낸다. 한글처럼 비ASCII 문자만 UTF-8 퍼센트 인코딩한다. 이미 있는 `%xx`는 건드리지 않는다.
- 근거: HTTP 헤더는 latin-1만 담을 수 있어 비ASCII를 그대로 넣으면 500 오류가 난다. 퍼센트 인코딩은 같은 주소를 가리킨다. 공백과 제어 문자는 D-2에서 이미 거절되므로 헤더에 넣어도 안전하다.
- 개정 (리뷰 1라운드, R-1): 처음에는 Starlette `RedirectResponse`를 그대로 썼다. 그런데 이 클래스는 `|`, `<`, `{` 같은 ASCII 문자까지 인코딩해서 AC-10("Location 헤더에 원래 URL")과 어긋났다. 그래서 비ASCII만 인코딩하도록 바꿨다.

## D-4. 오류 응답 형식

- 설계서: `422`만 정함.
- 결정: API는 `{"detail": "<한국어 문구>"}`, 화면은 같은 문구를 오류 메시지로 표시한다. 문구는 `F1-plan.md` 3.2의 표를 따른다.

## D-5. 없는 코드의 404 응답

- 설계서: API 절은 "`404 Not Found`", 화면 절(AC-21)은 "404 HTML 화면"
- 결정: `GET /{code}`는 하나의 경로이므로, 없는 코드는 항상 `404` HTML 찾을 수 없음 화면을 돌려준다. 7자가 아닌 코드도 같다.

## D-6. 입력칸 종류

- 결정: `type="url"` 대신 `type="text" inputmode="url"`을 쓰고 `required`를 붙이지 않는다.
- 근거: 브라우저 자체 검증 말풍선 대신 서버 검증 문구(한국어)가 일관되게 보이도록 한다. 모바일에서는 `inputmode="url"`로 URL 키보드가 뜬다.

## D-7. 폼에 `url` 필드가 없을 때

- 결정: 빈 문자열로 보고 `422` HTML 입력 오류 화면("URL을 입력해 주세요.")을 돌려준다. FastAPI 기본 JSON 422가 나가지 않게 한다.

## D-8. 유효하지 않은 유니코드(서로게이트)

- 상황: 리뷰 1라운드 S-1. JSON 문자열 `\ud800`처럼 짝이 없는 서로게이트(U+D800–U+DFFF)가 든 URL은 검증을 통과했다. 그 뒤 SQLite에 저장할 때 인코딩 오류가 나서 500이 됐다.
- 결정: 검증 4번 단계에서 서로게이트가 든 URL을 `422`로 거절한다. 문구는 `URL에 쓸 수 없는 문자가 들어 있습니다.`이다. 공백·제어 문자 검사보다 먼저 한다.
- 근거: 설계서는 잘못된 입력을 422로 거절하고 아무것도 저장하지 않도록 정한다. 500은 정의된 응답이 아니다.

## H3. 리뷰 1라운드 우선순위 (auto)

- 수정: R-1 [major], S-1 [minor→major로 올림]
  - S-1을 올린 이유: 경계 입력에 대해 422가 아닌 500을 돌려준다. qa 기준표의 major("오류 응답이나 경계 상황에서 잘못 동작함")에 해당한다.
- 기록만 (minor): R-2, R-3, R-4, R-5, S-2, S-3, S-4, S-5, S-6
  - S-3, S-4, S-6은 정책 사항이거나 F3 범위다.
