### 확인한 것

- 7종 모두 에이전트 정의의 모델로 실행되었고, 보고는 정해진 형식을 따랐습니다.
- hook은 실행됩니다. 다만 여러 에이전트가 동시에 한 파일에 기록하면 줄이 섞여서, 이벤트마다 별도 파일로 쓰도록 바꿨습니다. 병렬 12개 기록으로 다시 검증했습니다.
- 에이전트들이 스스로 짚은 한계: 쓰기 영역 hook은 Write/Edit만 막고 Bash를 통한 쓰기는 막지 못합니다.
- 데스크톱 앱 auto 권한 모드가 서브에이전트에게 "파일 작업은 Bash로 하라"는 지침을 주입합니다. 실험 권한 모드를 정할 때 고려해야 합니다.
- 이 세션은 git 초기화 전에 시작되어, 에이전트가 받은 환경 정보에 "git 저장소 아님"으로 표시됐습니다. 새 세션에서는 해당하지 않습니다.

## 실행 격리 강화

연구자가 "요즘 AI는 접근 권한이 있는 다른 폴더도 읽는데, git 범위 밖이라고 다를까"라고 문제를 제기했습니다. 점검해 보니 생각보다 쉬운 통로가 있었습니다. 실험 worktree는 연구 저장소와 git 이력을 공유해서, `git log`만 해도 연구 커밋이 보이고 `git show main:research/eval/...`로 평가 테스트를 그대로 읽을 수 있었습니다.

| 조치 | 내용 |
|---|---|
| 출발 커밋 | 실행 브랜치를 에이전트용 파일만 담은 부모 없는 커밋에서 시작. 저장소는 늘리지 않음 (연구자 요청) |
| hook | 실험 worktree에서 다른 브랜치·전체 이력·연구 저장소 경로 접근, 밖의 파일 읽기를 차단 |
| 표식 | 평가 테스트에 고유 표식과 `test_hidden_` 이름. 도구 결과에 나오면 그 실행을 무효 |
| main 반영 | 이력을 공유하지 않으므로 `promote.py`가 패치로 적용 |

검증(저장소 복제본): 실행 안 `git log`에 출발 커밋만 보임, 위험한 명령 차단, 체크포인트 집계, main이 앞서 나간 상태에서 반영, F2 실행에 F1 결과와 F1·F2 설계서만 포함됨을 확인. 도중에 Windows 텍스트 입력의 줄바꿈 변환 때문에 출발 커밋이 비는 버그를 찾아 고쳤습니다.

## F1-auto-r1 1차 시도 무효: hook 경로 비교 버그

- 증상: 구현 단계에서 implementer와 test-writer가 프로젝트 안 파일(설계서, 계획)을 절대 경로로 읽으려 하자 읽기 hook이 "연구 저장소 경로"라며 막음. 두 에이전트 모두 아무것도 바꾸지 못하고 돌아옴
- 원인: 연구 저장소 경로(`.../dev/agent-pipeline-lab`)가 실행 폴더 경로(`.../dev/agent-pipeline-lab-runs/...`)에 글자 그대로 들어 있는데, hook이 부분 문자열로만 비교함. 검증할 때 실행 폴더를 임시 폴더에 두어 이 배치를 재현하지 못했음
- 메인 세션의 행동: 원인을 정확히 진단하고 서브에이전트에게 "Bash 상대 경로로 읽으라"고 우회 지시를 시도 → auto 권한 분류기가 hook 우회로 보고 거부 → 메인은 더 우회하지 않고 멈춘 뒤 사람에게 세 가지 선택지를 제시함. 자율 모드였지만 사람 개입이 생겼으므로 이 실행은 무효
- 조치: 경로를 경계까지 비교하도록 수정, 실제 형제 폴더 배치로 회귀 테스트 22개(`research/infra_tests`). 이미 공개된 `baseline-F1` 태그를 옮기는 것은 차단되어, 고친 출발점에 `baseline-F1.1`을 새로 붙임. 쓰지 않은 F1 worktree 3개는 새 출발점에서 다시 만듦
- 무효 실행의 기록은 보존해서 사례 데이터로 씀 (막힌 상황에서 메인이 진단하고 멈춘 과정)
- 연구자가 실행 세션을 닫을 때 데스크톱 앱이 세션을 삭제해 트랜스크립트가 지워짐. 계획·결정 기록·목업(실행 폴더), 체크포인트 커밋(브랜치 `invalid/F1-auto-r1-hookbug`), 메인 세션의 마지막 보고(연구자가 붙여 넣은 내용)만 `research/runs/F1/invalid/auto-r1-hookbug/`에 보존. 실행 안내서에 "수집 완료 전 세션 삭제 금지, 닫을 때는 보관" 추가
- F1-auto-r1을 `baseline-F1.1`에서 다시 만듦. F1 실행 4개의 출발 파일 구성이 다시 같아짐
