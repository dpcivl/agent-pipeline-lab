# F3 — API 키 인증, 만료, 삭제, 관리 화면

| 항목 | 내용 |
|---|---|
| 버전 | v1.1 (2026-10-29) 확정 |
| 선행 기능 | F1, F2 |
| 작성 | 연구 세션(Claude)이 초안 작성, 연구자가 검토 후 확정 |

## 목적

링크를 만든 사람이 자기 링크를 관리할 수 있게 합니다. API 키로 링크의 소유자를 구분하고, 만료 시각을 정하거나 링크를 지울 수 있게 합니다. 남용을 막기 위해 생성 요청 수도 제한합니다. 보안 요소가 많은 기능입니다.

## 요구사항

### 설정 (고정 계약 확장)

`Settings`에 다음 필드를 추가합니다. 기존 필드는 바꾸지 않습니다.

| 필드 | 타입 | 환경 변수 | 기본값 |
|---|---|---|---|
| `api_keys` | `tuple[str, ...]` | `SHORTLINK_API_KEYS` (쉼표로 구분) | 빈 튜플 |
| `rate_limit_per_minute` | `int` | `SHORTLINK_RATE_LIMIT` | `120` |

- 키 하나가 소유자 한 명입니다. 키는 비밀 값이므로 응답, 화면, 로그에 그대로 내보내지 않습니다.
- 키 비교는 타이밍 공격에 안전한 방식으로 합니다.

### 소유자가 있는 링크

- `POST /links`에 `X-API-Key` 헤더로 등록된 키를 보내면, 만든 링크의 소유자는 그 키입니다.
- 키 없이 만든 링크는 소유자가 없습니다(F1·F2와 같음). 키 없이 만드는 것도 계속 허용합니다.
- 등록되지 않은 키를 보내면 `401`로 거절하고 아무것도 저장하지 않습니다.

### 만료

- `POST /links` 본문에 선택 필드 `expires_at`(UTC ISO 8601, 예: `2026-12-31T00:00:00Z`)을 받습니다.
- 과거나 지금 시각이면 `422`입니다. 형식이 틀려도 `422`입니다.
- 만료 시각이 지나면
  - `GET /{code}`는 `410 Gone`과 "만료된 링크입니다" 안내 화면을 보여 줍니다. 클릭 수는 늘지 않습니다.
  - 통계 API와 통계 화면은 그대로 보이고, 통계 API 응답에 `expires_at`과 `expired`(참/거짓)가 들어갑니다.
- 만료 시각이 없는 링크의 통계 API 응답에는 `expires_at: null`, `expired: false`가 들어갑니다.
- 생성 응답에도 `expires_at`(없으면 `null`)을 넣습니다.

### 삭제

- `DELETE /links/{code}`, `X-API-Key` 헤더 필요
  - 키가 없으면 `401`
  - 등록되지 않은 키면 `401`
  - 키는 맞지만 그 링크의 소유자가 아니거나, 소유자가 없는 링크면 `403`
  - 없는 코드면 `404`
  - 성공하면 `204`
- 지운 링크는 `GET /{code}`, 통계 API, 통계 화면 모두 `404`입니다.
- 지운 코드나 별칭은 다시 쓸 수 있습니다.

### 요청 수 제한

- 링크 생성 요청(`POST /links`와 화면의 `POST /`)을 클라이언트 IP마다 1분에 `rate_limit_per_minute`번까지 허용합니다.
- 넘으면 `429 Too Many Requests`와 `Retry-After` 헤더(초)로 거절하고 저장하지 않습니다. 화면 요청이면 같은 상태 코드의 홈 화면에 안내 문구를 보여 줍니다.
- 리다이렉트, 통계 조회는 제한하지 않습니다.
- 요청 수 기록은 앱 인스턴스(`create_app()`으로 만든 앱)마다 따로 관리합니다. 한 앱의 기록이 다른 앱에 영향을 주지 않습니다.

### 관리 화면

- `GET /manage`: API 키를 입력하는 폼(`name="api_key"`, 비밀번호 입력칸, 라벨 "API 키")
- `POST /manage`: 올바른 키면 그 키가 소유한 링크 목록을 보여 줍니다. 각 줄에 단축 URL, 원래 URL, 클릭 수, 생성 시각, 만료 시각(없으면 "없음", 지났으면 "만료됨"), "삭제" 버튼이 있습니다. 틀린 키면 `401` 화면에 오류 메시지를 보여 줍니다.
- 삭제 버튼은 `POST /manage/delete` 폼으로 삭제하고, 성공하면 갱신된 목록을 보여 줍니다. 권한 규칙은 `DELETE /links/{code}`와 같습니다.
- 관리 화면의 어떤 응답에도 API 키 값이 HTML에 그대로 나오지 않아야 합니다. 키를 화면 사이에 전달해야 하면 안전한 방법을 택하고 그 방법을 결정 기록에 남깁니다.
- 홈 화면에 관리 화면으로 가는 "내 링크 관리" 링크를 추가합니다.

### 호환성

F1과 F2의 요구사항을 계속 지켜야 합니다.

## 수용 기준

인증과 소유:

- **AC-1** 등록된 키로 `POST /links`하면 `201`이다. 키 없이 만드는 것도 계속 `201`이다.
- **AC-2** 등록되지 않은 키로 `POST /links`하면 `401`이고 아무것도 저장하지 않는다.
- **AC-3** 생성 응답과 통계 API 응답, 모든 화면에 API 키 값이 나오지 않는다.

만료:

- **AC-4** 미래의 `expires_at`으로 만들면 `201`이고 응답에 같은 시각의 `expires_at`이 있다. 만료 전에는 `302`로 리다이렉트된다.
- **AC-5** 과거 시각이나 형식이 틀린 `expires_at`은 `422`다.
- **AC-6** 만료 시각이 지난 링크의 `GET /{code}`는 `410` HTML 화면에 "만료된 링크입니다"를 보여 주고, 클릭 수를 늘리지 않는다.
- **AC-7** 통계 API 응답에 `expires_at`과 `expired`가 있다. 만료 전 `false`, 만료 후 `true`, 만료 시각이 없으면 `expires_at: null`, `expired: false`다.

삭제:

- **AC-8** 소유자 키로 `DELETE /links/{code}`하면 `204`이고, 이후 리다이렉트, 통계 API, 통계 화면이 모두 `404`다.
- **AC-9** 키 없이 삭제하면 `401`, 등록되지 않은 키면 `401`이다.
- **AC-10** 다른 소유자의 키로 지우거나 소유자가 없는 링크를 지우려 하면 `403`이고 링크는 그대로 동작한다.
- **AC-11** 없는 코드를 지우려 하면 `404`다.
- **AC-12** 지운 별칭으로 새 링크를 다시 만들 수 있다.

요청 수 제한:

- **AC-13** `rate_limit_per_minute=3`으로 만든 앱에서 같은 클라이언트가 1분 안에 생성 요청을 4번 하면 4번째는 `429`이고 `Retry-After` 헤더가 있으며 저장되지 않는다. API와 화면 생성 요청이 같은 한도를 함께 쓴다.
- **AC-14** 한도를 넘은 뒤에도 리다이렉트와 통계 조회는 정상이다.

관리 화면:

- **AC-15** `GET /manage`는 `200` HTML 화면에 `<label>`이 붙은 `name="api_key"` 비밀번호 입력칸이 있다.
- **AC-16** 올바른 키로 `POST /manage`하면 그 키가 소유한 링크만 목록에 보이고, 다른 소유자의 링크와 소유자가 없는 링크는 보이지 않는다.
- **AC-17** 틀린 키로 `POST /manage`하면 `401` HTML 화면에 오류 메시지가 보인다.
- **AC-18** 관리 화면에서 삭제하면 그 링크가 지워지고 목록에서 사라진다. 다른 소유자의 링크는 관리 화면으로 지울 수 없다.
- **AC-19** 관리 화면의 목록은 원래 URL을 이스케이프해서 보여 주고, 만료된 링크는 "만료됨"으로 표시한다.
- **AC-20** 홈 화면에 `/manage`로 가는 "내 링크 관리" 링크가 있다.
- **AC-21** 관리 화면과 만료 안내 화면은 `<html lang="ko">`와 viewport meta를 갖는다.

호환성:

- **AC-22** F1과 F2의 수용 기준을 모두 계속 만족한다. (F1·F2 평가 테스트를 함께 실행해 확인. F3 기능 기본값에서)

## 범위 밖

- 키 발급·교체 화면, 사용자 계정과 로그인
- 링크 수정 (URL이나 만료 시각 변경)
- 분산 환경의 요청 수 제한 (프로세스 하나 기준이면 충분)
