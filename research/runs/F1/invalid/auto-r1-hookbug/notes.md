# F1-auto-r1 1차 시도 — 무효 (hook 경로 비교 버그)

- 날짜: 2026-10-29 · 출발점 `baseline-F1` (버그 있음) · 자율 모드
- 결과: 2단계(구현·테스트 작성)에서 중단. 무효 처리하고 `baseline-F1.1`에서 다시 실행

## 남은 기록

| 기록 | 위치 | 비고 |
|---|---|---|
| 계획, 결정 기록, 목업 | `artifacts/` | 실행 폴더의 `docs/plans/`를 복사. 결정 기록의 E-1(이 문제)은 커밋되지 않은 변경이었음 |
| 체크포인트 커밋 | 브랜치 `invalid/F1-auto-r1-hookbug`의 `1ca2b3c` (`wip(F1): 1 계획, 스켈레톤, 목업`) | |
| 메인 세션의 마지막 보고 | 아래 요약 | 연구자가 연구 세션에 붙여 넣은 내용 |
| 트랜스크립트 | **없음** | 연구자가 세션을 닫을 때 데스크톱 앱이 세션을 삭제하면서 대화 기록도 지워짐. 그래서 메시지, 토큰, 비용은 수집하지 못함 |

## 무슨 일이 있었나 (메인 세션 보고 요약)

1. 1단계(계획, 스켈레톤, 목업)를 마치고 체크포인트 커밋을 만듦
2. 2단계에서 implementer와 test-writer가 프로젝트 안의 설계서, 계획, 결정 기록을 절대 경로로 읽으려 했으나 읽기 hook(`guard_read.py`)이 "research repository path"라며 거부. 두 에이전트는 파일을 하나도 바꾸지 못하고 돌아옴
3. 메인 세션은 원인을 정확히 진단함: 연구 저장소 루트 `.../dev/agent-pipeline-lab`이 실행 폴더 `.../dev/agent-pipeline-lab-runs/F1-auto-r1`의 경로에 글자 그대로 들어 있고, `runscope.mentions_research`가 부분 문자열로만 비교함
4. 메인 세션은 서브에이전트에게 "Bash에서 상대 경로로 읽으라"고 다시 지시하려 했으나, auto 권한 분류기가 이를 hook 우회로 보고 거부
5. 메인 세션은 더 우회하지 않고 멈춘 뒤, 사람에게 세 가지 선택지(hook 수정 후 재개 / 이번 실행만 Bash 읽기 허용 / 실패로 기록)를 제시함. hook 파일은 연구 인프라이고 어느 역할의 쓰기 영역도 아니라며 건드리지 않음

## 의미

- 실험 인프라의 버그로 인한 무효 실행이므로 비교 실험의 집계에서 제외합니다.
- 다만 "막힌 상황에서 메인이 진단 → 우회 시도 → 분류기 거부 → 사람에게 넘김"으로 이어진 과정은 자율 모드의 한계와 안전장치가 함께 드러난 사례로 보고서에서 다룹니다.

## 재발 방지

- hook: 경로를 경계까지 비교하도록 수정, 실제 폴더 배치로 회귀 테스트 (`research/infra_tests`)
- 실행 안내서: 수집이 끝날 때까지 세션을 닫지 않고, 닫을 때는 삭제하지 않도록 명시
