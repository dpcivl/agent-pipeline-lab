# F1 — 단축 URL 생성과 리다이렉트

| 항목 | 내용 |
|---|---|
| 버전 | v2 (2026-10-29) 확정 |
| 선행 기능 | 없음 |
| 작성 | 연구 세션(Claude)이 초안 작성, 연구자가 검토 후 확정 |

## 목적

긴 URL을 짧은 코드로 바꿔 저장하고, 짧은 URL로 접속하면 원래 URL로 보내 주는 ShortLink의 가장 기본 기능을 만듭니다. 사용자는 **웹 화면**에서 URL을 줄일 수 있고, 다른 프로그램은 **JSON API**로 같은 기능을 씁니다. 이후 기능(F2 통계·별칭, F3 인증·만료·삭제)은 이 기능 위에 쌓입니다.

## 요구사항

### 단축 URL 생성

- 요청: `POST /links`, 본문 JSON `{"url": "<원래 URL>"}`
- 성공 응답: `201 Created`, 본문 JSON

  | 필드 | 내용 |
  |---|---|
  | `code` | 단축 코드. 영문 대소문자와 숫자로 된 7자 |
  | `short_url` | `<Settings.base_url>/<code>` |
  | `url` | 요청한 원래 URL 그대로 |
  | `created_at` | 생성 시각. UTC, ISO 8601 형식 (예: `2026-10-29T01:23:45Z`) |

- 코드는 예측하기 어려운 무작위 값으로 만들고, 이미 있는 코드와 겹치면 다시 만듭니다.
- 같은 URL을 여러 번 요청하면 요청마다 새 코드를 만듭니다. 중복을 합치지 않습니다.

### URL 검증

다음 중 하나라도 해당하면 `422 Unprocessable Entity`로 거절하고 아무것도 저장하지 않습니다.

- `url` 필드가 없거나, 문자열이 아니거나, 빈 문자열
- 스킴이 `http` 또는 `https`가 아님 (예: `ftp:`, `javascript:`, `data:`, `mailto:`)
- 호스트가 없음 (예: `https://`)
- 길이가 2,048자를 넘음

URL은 받은 그대로 저장하고 돌려줍니다. 앞뒤 공백 제거, 대소문자 변경 같은 정규화는 하지 않습니다.

### 리다이렉트

- 요청: `GET /{code}`
- 코드가 있으면 `302 Found`와 `Location: <원래 URL>` 헤더로 응답합니다.
- 코드가 없으면 `404 Not Found`로 응답합니다.

### 웹 화면

화면은 한국어로 만들고, 서버에서 Jinja2 템플릿으로 HTML을 만들어 보냅니다(`src/shortlink/templates/`, CSS는 `src/shortlink/static/`).

| 화면 | 경로 | 내용 |
|---|---|---|
| 홈 | `GET /` | 서비스 이름, 한 줄 설명, URL 입력 폼 |
| 결과 | `POST /` 성공 | 만든 단축 URL(링크), 원래 URL, "복사" 버튼, "다른 URL 줄이기" 링크 |
| 입력 오류 | `POST /` 실패 | 홈 화면에 오류 메시지를 함께 표시하고, 입력했던 값을 입력칸에 남김 |
| 찾을 수 없음 | 없는 코드로 `GET /{code}` | "링크를 찾을 수 없습니다" 안내와 홈으로 가는 링크 |

- 입력 폼: `<form method="post" action="/">`, 입력칸 `name="url"`에 `<label>`을 붙이고, 제출 버튼 문구는 "줄이기"입니다.
- 폼 제출은 API와 같은 검증 규칙을 따르고, 같은 저장소에 저장합니다. 화면에서 만든 링크도 `GET /{code}`로 리다이렉트됩니다.
- 사용자가 입력한 값은 HTML에 그대로 넣지 않고 이스케이프해서 표시합니다.
- "복사" 버튼은 단축 URL을 클립보드에 복사합니다(브라우저 JavaScript). JavaScript가 꺼져 있어도 단축 URL 링크는 보여야 합니다.
- 모든 페이지는 `<html lang="ko">`와 viewport meta를 갖고, 폭 375px 화면에서도 가로 스크롤 없이 쓸 수 있어야 합니다.

### 저장

- `Settings.db_path`의 SQLite 파일에 저장합니다. 표준 라이브러리 `sqlite3`를 쓰고 ORM은 쓰지 않습니다.
- 같은 `db_path`로 앱을 새로 만들어도 이전에 만든 코드로 리다이렉트할 수 있어야 합니다.
- 고정 계약(`CLAUDE.md`)을 지킵니다. 특히 `create_app()`은 라우터 등록과 DB 스키마 준비까지 끝낸 앱을 돌려줘야 합니다.

## 수용 기준

- **AC-1** `POST /links`에 `{"url": "https://example.com/path?q=1"}`을 보내면 `201`과 함께 `code`, `short_url`, `url`, `created_at`을 돌려준다.
- **AC-2** `code`는 영문 대소문자와 숫자로 된 7자이고, `short_url`은 `<Settings.base_url>/<code>`와 같다.
- **AC-3** 응답의 `url`은 요청한 URL과 글자 그대로 같다.
- **AC-4** `http://` URL도 생성된다.
- **AC-5** 스킴이 `http`나 `https`가 아닌 URL(`ftp://example.com`, `javascript:alert(1)`, `data:text/html,hi`, `mailto:a@example.com`)은 `422`로 거절된다.
- **AC-6** `url` 필드가 없거나, 문자열이 아니거나(예: 숫자), 빈 문자열이면 `422`로 거절된다.
- **AC-7** 호스트가 없는 URL(`https://`)은 `422`로 거절된다.
- **AC-8** 2,048자인 URL은 생성되고, 2,049자인 URL은 `422`로 거절된다.
- **AC-9** 거절된 요청은 아무것도 저장하지 않는다.
- **AC-10** `GET /{code}`는 `302`와 함께 `Location` 헤더에 원래 URL을 돌려준다.
- **AC-11** 존재하지 않는 코드로 `GET`하면 `404`를 돌려준다.
- **AC-12** 같은 URL을 두 번 생성하면 서로 다른 코드가 나오고, 두 코드 모두 원래 URL로 리다이렉트된다.
- **AC-13** 100번 연속 생성한 코드는 모두 서로 다르다.
- **AC-14** 같은 `db_path`로 앱을 새로 만든 뒤에도 이전에 만든 코드로 리다이렉트된다.
- **AC-15** `created_at`은 UTC ISO 8601 형식이고 생성 요청 시각과 1분 이상 차이 나지 않는다.

웹 화면:

- **AC-16** `GET /`는 `200`과 HTML(`text/html`)을 돌려주고, `/`로 POST하는 폼, `<label>`이 붙은 `name="url"` 입력칸, "줄이기" 제출 버튼을 담는다.
- **AC-17** 폼으로 올바른 URL을 제출하면 `200` 결과 화면에 `href`가 단축 URL인 링크와 원래 URL이 보인다.
- **AC-18** 결과 화면에는 "복사" 버튼과 홈(`/`)으로 가는 "다른 URL 줄이기" 링크가 있다.
- **AC-19** 폼으로 잘못된 URL을 제출하면 `422` HTML 화면에 오류 메시지가 보이고, 입력칸에 제출한 값이 남아 있으며, 아무것도 저장되지 않는다.
- **AC-20** `<script>`처럼 HTML 특수문자가 든 URL을 제출해도 결과 화면과 오류 화면에 이스케이프되어 표시된다(원문 `<script>` 태그가 HTML에 그대로 나오지 않는다).
- **AC-21** 없는 코드로 `GET /{code}`하면 `404` HTML 화면에 안내 문구와 홈으로 가는 링크가 있다.
- **AC-22** 모든 화면은 `<html lang="ko">`와 viewport meta를 갖는다.
- **AC-23** 폼으로 만든 단축 코드도 `GET /{code}`로 원래 URL에 리다이렉트된다.
