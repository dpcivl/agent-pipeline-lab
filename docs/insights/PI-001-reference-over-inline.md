# PI-001 — 메인은 내용을 붙여 넣지 않고 파일을 가리킨다

| 항목 | 내용 |
|---|---|
| 상태 | 가설 |
| 확신도 | 1개 실행, 7개 지시 |
| 관련 질문 | Q6, Q7 |
| 코드북 태그 | S-REF, C-INPUT |

## 관찰

파일럿에서 메인이 보낸 지시 7개는 설계서, 구현 계획, 목업을 모두 파일 경로로 가리켰고, 내용을 붙여 넣지 않았습니다. 지시 하나의 평균 길이는 약 450토큰이었습니다.

## 근거

| 실행 | 메시지 | 요약 |
|---|---|---|
| `runs/F1/default/r2` | `messages/003-main-to-implementer-T-TASK.md` | "기준 문서" 절에서 설계서, 계획, 목업 4개를 경로로만 지정 |
| `runs/F1/default/r2` | `messages/007-main-to-tester-T-TASK.md` | 판단 근거를 "설계서와 계획 7절"로 가리킴 |

## 해석

서브에이전트는 같은 저장소를 읽을 수 있으므로, 메인은 공유 파일을 소통 수단으로 씁니다. 지시는 짧아지지만 받는 쪽이 파일을 직접 읽어야 하므로, 그 비용은 서브에이전트의 cache write와 read로 옮겨 갑니다.

## 사람이 프롬프트를 쓸 때의 시사점

- 에이전트가 같은 저장소를 볼 수 있다면, 긴 설명을 붙여 넣기보다 "어느 파일의 어느 절을 따르라"고 가리키는 편이 지시를 짧고 정확하게 만듭니다.
- 대신 가리키는 문서 자체가 정리되어 있어야 합니다(계획 문서의 절 번호, 결정 번호 D-1 등).

## 반례와 한계

- 아직 실행 1개뿐입니다. 테스트 실패를 전달하는 수정 요청에서도 같은 방식인지(에러 출력을 붙여 넣는지)는 확인하지 못했습니다.
