# 메시지 코드북 (초안 v0.1)

에이전트 간 메시지를 분류하고 코딩하는 기준입니다. 파일럿 실행(P3)의 실제 메시지로 보완한 뒤 확정합니다. 확정 후 바꾸면 버전을 올리고 이전 코딩을 다시 합니다.

## 1. 메시지 종류 (type)

| 코드 | 이름 | 방향 | 설명 |
|---|---|---|---|
| T-TASK | 최초 지시 | 메인 → 서브 | 단계의 첫 작업 지시 |
| T-FIX | 수정 요청 | 메인 → implementer, test-writer | 테스트 실패나 findings를 근거로 한 수정 지시 |
| T-RERUN | 재실행 요청 | 메인 → tester | 수정 후 다시 테스트하라는 지시 |
| T-REREVIEW | 재검토 요청 | 메인 → reviewer, qa, security | 2라운드 이후 변경분 검토 지시 |
| T-CLARIFY | 확인 질문 | 서브 → 메인, 메인 → 사람 | 정보가 부족해 묻는 메시지 |
| R-DONE | 완료 보고 | 서브 → 메인 | 작업 완료 보고 |
| R-FAIL | 실패 보고 | tester → 메인 | 실패 목록과 원인 분류 |
| R-FINDINGS | 지적 보고 | reviewer, qa, security → 메인 | 심각도가 붙은 findings |
| H-INPUT | 사람 메시지 | 사람 → 메인 | 개입 모드의 사람 입력 |

## 2. 지시 구성 요소 (component) — 지시 메시지(T-*)에 표시

메시지마다 각 요소가 있으면 1, 없으면 0으로 표시합니다.

| 코드 | 요소 | 판단 기준 |
|---|---|---|
| C-GOAL | 목표 | 무엇을 해야 하는지 한 문장 이상 |
| C-WHY | 이유·배경 | 왜 이 작업이 필요한지 |
| C-CONTEXT | 이전 맥락 | 앞 단계나 이전 라운드에서 일어난 일 요약 |
| C-INPUT | 입력 참조 | 읽어야 할 파일 경로나 문서 지정 |
| C-SCOPE | 범위·제약 | 수정 가능한 파일, 하지 말아야 할 일 |
| C-DONE | 완료 조건 | 언제 끝난 것으로 볼지 |
| C-FORMAT | 출력 형식 | 보고를 어떤 형식으로 할지 |
| C-PRIORITY | 우선순위 | 여러 항목 중 무엇을 먼저 할지 |
| C-EVIDENCE | 근거 첨부 | 에러 메시지, 테스트 출력, 코드 조각 등 |
| C-HINT | 해결 힌트 | 어떻게 고칠지에 대한 제안 |

## 3. 전달 방식 (style)

| 코드 | 설명 |
|---|---|
| S-REF | 내용을 파일 경로로 가리킴 |
| S-INLINE | 내용(코드, 로그, 설계서 일부)을 메시지에 직접 붙여 넣음 |
| S-MIXED | 둘 다 사용 |

추가 기록: 메시지 토큰 수, 글자 수, 목록·표 사용 여부, 언어(한국어/영어).

## 4. 중계 변형 (relay) — 보고와 그 보고를 근거로 쓴 다음 지시의 쌍에 표시

보고 안의 정보 항목마다 다음 지시에서 어떻게 되었는지 표시합니다.

| 코드 | 설명 |
|---|---|
| X-KEEP | 그대로 전달 |
| X-SUMMARY | 요약해서 전달 |
| X-DROP | 빠짐 |
| X-ADD | 보고에 없던 내용이 메인의 판단으로 추가됨 |
| X-REINTERPRET | 의미가 바뀌어 전달됨 |
| X-REPRIORITIZE | 우선순위가 바뀜 |

## 5. 코딩 절차

1. 별도 LLM 세션이 `messages.jsonl`을 읽고 이 코드북으로 1차 코딩 → `annotations.csv`
2. 사람이 무작위 20%를 검수하고 불일치를 기록
3. 불일치가 많은 코드는 정의를 고치고 다시 코딩
