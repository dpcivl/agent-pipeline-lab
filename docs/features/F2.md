# F2 — 클릭 통계와 커스텀 별칭

| 항목 | 내용 |
|---|---|
| 버전 | v1 초안 (2026-10-29), 검토 대기 |
| 선행 기능 | F1 |
| 작성 | 연구 세션(Claude)이 초안 작성, 연구자 검토 |

## 목적

사용자가 단축 링크가 몇 번 쓰였는지 확인하고, 기억하기 쉬운 코드를 직접 정할 수 있게 합니다. F1에서 만든 생성, 리다이렉트, 화면을 **고쳐서** 기능을 더하는 작업입니다.

## 요구사항

### 커스텀 별칭

- API: `POST /links` 본문에 선택 필드 `alias`를 받습니다. 예: `{"url": "https://example.com", "alias": "my-link"}`
- 화면: 홈 화면 폼에 선택 입력칸 `name="alias"`(라벨 "별칭 (선택)")을 추가합니다.
- 별칭을 주면 그 값이 코드가 됩니다. 응답의 `code`와 `short_url`도 별칭을 씁니다.
- 별칭을 주지 않으면 F1과 같이 7자 무작위 코드를 만듭니다.
- 별칭 규칙
  - 길이 4~30자
  - 영문 대소문자, 숫자, 하이픈(`-`)만 허용. 하이픈으로 시작하거나 끝날 수 없음
  - 대소문자를 구분합니다 (`My-Link`와 `my-link`는 다른 별칭)
  - 예약어는 쓸 수 없음: `links`, `static`, `stats`, `docs`, `redoc`, `openapi.json`, `api`, `admin`, `manage`
- 규칙 위반은 `422`, 이미 쓰이는 코드나 별칭이면 `409 Conflict`로 거절하고 아무것도 저장하지 않습니다.
- 화면에서 거절되면 같은 상태 코드(`422` 또는 `409`)의 홈 화면에 오류 메시지를 보이고, 입력했던 URL과 별칭을 입력칸에 남깁니다.

### 클릭 통계

- `GET /{code}`로 리다이렉트할 때마다 그 링크의 클릭 수를 1 늘리고 마지막 접근 시각을 기록합니다. `404`인 경우는 세지 않습니다.
- 통계 API: `GET /links/{code}/stats`
  - 성공: `200` JSON

    | 필드 | 내용 |
    |---|---|
    | `code` | 코드 또는 별칭 |
    | `url` | 원래 URL |
    | `short_url` | 단축 URL |
    | `clicks` | 클릭 수 (정수, 처음에는 0) |
    | `created_at` | 생성 시각 (F1과 같은 형식) |
    | `last_accessed_at` | 마지막 접근 시각 (같은 형식), 접근한 적이 없으면 `null` |

  - 없는 코드: `404`
  - 통계 조회는 클릭 수를 늘리지 않습니다.
- 통계 화면: `GET /stats/{code}`
  - 단축 URL, 원래 URL, 클릭 수, 생성 시각, 마지막 접근 시각(없으면 "아직 없음")을 보여 줍니다.
  - 없는 코드면 `404` 찾을 수 없음 화면(F1과 같음)을 보여 줍니다.
- F1 결과 화면에 "통계 보기" 링크(`/stats/{code}`)를 추가합니다.

### 호환성

- F1의 요구사항(AC-1~AC-23)은 그대로 지켜야 합니다. 단, F1에서 "7자 영숫자가 아닌 경로는 무조건 404"처럼 구현했다면, 별칭으로 만든 코드가 리다이렉트되도록 고쳐야 합니다.
- F1 시절에 만든 데이터베이스 파일로 앱을 시작해도 기존 링크가 동작해야 하고, 그 링크의 클릭 수는 0부터 셉니다. (이 항목은 평가 테스트가 아니라 리뷰와 QA에서 확인합니다.)

## 수용 기준

별칭:

- **AC-1** `POST /links`에 올바른 `alias`를 주면 `201`이고 `code`가 별칭과 같으며 `short_url`이 `<base_url>/<별칭>`이다.
- **AC-2** 별칭으로 만든 코드로 `GET /{별칭}`하면 `302`로 원래 URL에 리다이렉트된다.
- **AC-3** `alias`를 주지 않으면 F1과 같이 7자 영숫자 코드가 만들어진다.
- **AC-4** 3자 별칭과 31자 별칭은 `422`, 4자와 30자 별칭은 생성된다.
- **AC-5** 허용하지 않는 문자(공백, `_`, `/`, `.`, 한글 등)나 하이픈으로 시작·끝나는 별칭은 `422`다.
- **AC-6** 예약어 별칭은 `422`다.
- **AC-7** 이미 쓰이는 별칭으로 다시 만들면 `409`이고, 기존 링크는 그대로 원래 URL로 리다이렉트된다.
- **AC-8** 별칭은 대소문자를 구분한다. `My-Link`가 있어도 `my-link`는 만들 수 있고 둘은 각자의 URL로 리다이렉트된다.
- **AC-9** `422`나 `409`로 거절된 요청은 아무것도 저장하지 않는다.
- **AC-10** 홈 화면 폼에 `<label>`이 붙은 `name="alias"` 입력칸이 있고, 폼으로 별칭을 주면 결과 화면의 단축 URL에 별칭이 쓰인다.
- **AC-11** 폼으로 잘못된 별칭을 주면 `422`, 중복 별칭을 주면 `409` HTML 화면에 오류 메시지가 보이고, 입력했던 URL과 별칭이 입력칸에 남아 있다.

통계:

- **AC-12** 새 링크의 `GET /links/{code}/stats`는 `200`이고 `clicks`는 0, `last_accessed_at`은 `null`이다.
- **AC-13** `GET /{code}`를 3번 하면 `clicks`가 3이 되고 `last_accessed_at`이 채워진다.
- **AC-14** 통계 API를 여러 번 조회해도 `clicks`는 늘지 않는다.
- **AC-15** 없는 코드로 `GET /{code}`해도 어떤 링크의 클릭 수도 늘지 않는다.
- **AC-16** 없는 코드의 통계 API는 `404`다.
- **AC-17** `GET /stats/{code}`는 `200` HTML 화면에 클릭 수와 원래 URL을 보여 주고, 접근한 적이 없으면 "아직 없음"을 보여 준다.
- **AC-18** 없는 코드의 통계 화면은 `404` HTML 화면이다.
- **AC-19** 결과 화면에 `/stats/{code}`로 가는 "통계 보기" 링크가 있다.
- **AC-20** 같은 `db_path`로 앱을 새로 만들어도 클릭 수가 유지된다.
- **AC-21** 통계 화면도 원래 URL을 이스케이프해서 보여 준다.
- **AC-22** 통계 화면은 `<html lang="ko">`와 viewport meta를 갖는다.

호환성:

- **AC-23** F1의 수용 기준 AC-1~AC-23을 모두 계속 만족한다. (F1 평가 테스트를 함께 실행해 확인)
