# F1 설계서 해석 결정 기록

auto 모드에서 메인 세션이 내린 해석입니다. 설계서(`docs/features/F1.md` v2)가 정하지 않은 부분만 다룹니다.

## 실행 환경 문제

### E-1. 읽기 가드 훅의 오탐 (2단계 시작 시 발견)
- 현상: `research/hooks/guard_read.py`가 이 worktree 안의 파일을 절대 경로로 읽는 Read/Glob/Grep 호출을 모두 "research repository path"로 막음. implementer와 test-writer가 첫 호출에서 막혀 아무것도 하지 못하고 돌아옴.
- 원인: `runscope.mentions_research`가 연구 저장소 루트(`c:/users/<USER>/documents/dev/agent-pipeline-lab`)를 부분 문자열로 비교하는데, 이 worktree 경로(`c:/users/<USER>/documents/dev/agent-pipeline-lab-runs/F1-auto-r1/...`)가 그 문자열을 포함함.
- 시도한 조치: 서브에이전트에게 Bash의 상대 경로로 읽으라고 다시 지시하려 했으나, auto 모드 권한 분류기가 훅 우회로 보고 거부함(Auto-Mode Bypass).
- 상태: **사람 판단 대기.** 훅은 연구 인프라이고 어느 역할의 쓰기 영역도 아니므로 메인이 고치지 않는다. 파이프라인은 2단계에서 멈춰 있다.
- 연구자에게 알릴 사항: `runscope.mentions_research`가 경로를 구분자 경계까지 비교하도록 고쳐야 한다(예: `root + "/"`를 찾거나 정확히 일치하는지 확인).

## 계획 단계 (1단계)

### D-1. API 422 응답 본문 형식
- 설계서: 422로 거절한다고만 정함.
- 결정: `{"detail": "<한국어 메시지>"}`. 필드 없음·타입 오류도 FastAPI 기본 검증 목록 대신 같은 형식을 쓴다.
- 이유: 웹 화면과 같은 메시지를 공유하고, 클라이언트가 한 형식만 처리하면 된다.

### D-2. 공백·제어 문자가 든 URL
- 설계서: 정규화(앞뒤 공백 제거 등)를 하지 않는다고 정함. 공백이 든 URL의 처리는 정하지 않음.
- 결정: 공백(0x20)이나 제어 문자(0x00–0x1F, 0x7F)가 어디에든 있으면 422.
- 이유: 정규화 금지와 충돌하지 않으면서, `urlsplit`이 앞 공백을 무시해 검증을 통과하는 문제와 `Location` 헤더 주입(CR/LF)을 막는다. 공백은 RFC 3986상 URL에 쓸 수 없는 문자다.

### D-3. 스킴 대소문자
- 결정: `HTTP://`, `Https://`도 허용(스킴은 대소문자를 구분하지 않음, RFC 3986). 저장은 받은 그대로.

### D-4. 잘못된 형식
- 결정: `urlsplit`이 실패하는 URL(예: `http://[::1`)과 숫자가 아닌 포트(예: `http://example.com:abc`)는 422 "올바른 URL 형식이 아닙니다."

### D-5. `created_at` 정밀도
- 결정: 초 단위, `Z` 접미사(`2026-10-29T01:23:45Z`). 설계서 예시와 같은 형식.

### D-6. 없는 코드의 404 응답 형식
- 설계서: API 요구사항은 404만, 웹 화면은 404 HTML 안내 화면을 요구.
- 결정: `GET /{code}`의 404는 항상 HTML(찾을 수 없음 화면). 리다이렉트 경로는 API와 웹이 공유하는 하나의 경로이므로 분리하지 않는다.

### D-7. 비ASCII 문자가 든 URL의 리다이렉트
- 결정: 저장과 API 응답은 받은 그대로. `Location` 헤더에서만 비ASCII 문자를 UTF-8 퍼센트 인코딩한다(ASCII 문자는 그대로).
- 이유: HTTP 헤더는 latin-1만 담을 수 있어 그대로 보내면 서버 오류가 난다. 브라우저도 같은 방식으로 인코딩한다.

### D-8. 코드 형식이 아닌 경로
- 결정: `GET /{code}`에서 코드가 영숫자 7자가 아니면 DB 조회 없이 404 HTML.

### D-9. 웹 폼의 입력칸 타입
- 결정: `type="text"`, `inputmode="url"`, `required` 없음.
- 이유: 브라우저 자체 검증 대신 서버가 같은 한국어 메시지로 오류를 보여 주게 한다(입력 오류 화면이 실제로 쓰이도록).

### D-10. "복사" 버튼과 JavaScript
- 결정: 버튼은 항상 HTML에 있다. 스크립트는 `static/copy.js`(인라인 스크립트 없음). 복사 성공 시 버튼 문구를 잠시 "복사됨"으로 바꾼다. JavaScript가 꺼져도 단축 URL 링크는 보인다.
