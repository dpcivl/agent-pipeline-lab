# agent-pipeline-lab

사람과 Claude Code 서브에이전트가 함께 기능을 개발하는 파이프라인을 직접 만들어 보고, 에이전트끼리 주고받는 프롬프트와 토큰 사용량을 측정하는 연구 저장소입니다.

> **실험은 2026-10-30에 F2까지 하고 중단했습니다.** 결과는 [시험 보고서(docx)](research/pipeline-test-report.docx)와 [정리 보고서](research/REPORT.md)에 있습니다.

## 알고 싶은 것

- 에이전트끼리 실제로 어떤 프롬프트를 주고받는가
- 그 소통에 토큰이 얼마나 드는가
- 기능 하나를 끝까지 만드는 데 비용이 얼마인가
- 사람이 개입할 때와 하지 않을 때 결과물과 비용이 어떻게 다른가
- 에이전트끼리의 소통에서 사람이 배울 수 있는 효율적인 프롬프팅 패턴은 무엇인가

## 파이프라인

```
설계서(사람) → 계획·스켈레톤(메인) → 승인(사람)
→ [구현 ∥ 테스트 작성] → 테스트 루프 → [리뷰 ∥ QA ∥ 보안] 리뷰 루프
→ 문서·커밋 → 보고서
```

실험 대상은 웹 화면과 API를 함께 가진 URL 단축 웹 서비스(ShortLink)입니다. 기능 3개를 순서대로 만들 계획이었으나 F1(단축 URL 생성과 리다이렉트)과 F2(클릭 통계와 커스텀 별칭)까지만 실행했습니다. 메인 세션이 화면 목업을 만들고 사람이 확인한 뒤 구현에 들어갑니다. 웹·앱 개발 프로젝트에 이 파이프라인을 적용할 수 있는지 보는 것이 목적입니다.

## 결과 요약

유효한 실행 9개(F1 파일럿 1, F1 비교 4, F2 비교 4)를 근거로 합니다.

- **비용.** 기능 하나(API + 웹 화면 + 테스트 + 문서)에 API 단가 환산 $4.78~8.58, 650만~1,330만 토큰, 15~46분이 들었습니다. 비용의 약 절반은 메인 세션(Opus)에서 나왔습니다.
- **소통 토큰은 아주 작습니다.** 에이전트끼리 주고받은 메시지는 전체 토큰의 0.14~0.22%입니다. 토큰 대부분은 각 에이전트가 파일과 맥락을 반복해서 읽는 캐시 읽기였습니다.
- **비용을 가른 것은 리뷰 라운드 수입니다.** 1라운드에서 major 지적이 나와 수정과 2라운드 리뷰를 거친 실행은 평균 $7.13, 그렇지 않은 실행은 $5.60이었습니다.
- **검증.** 9개 실행 모두 숨긴 평가 테스트를 100% 통과했습니다. 리뷰 단계는 평가 테스트가 다루지 않는 결함(F1 서로게이트 문자로 인한 500, F2 동시 시작 시 마이그레이션 실패)을 찾았습니다.
- **중단 이유.** 개입(human) 실행에서도 사람이 메인 세션의 권장안을 그대로 골랐습니다. 그래서 자율(auto)과 개입의 차이가 사람 검토 유무가 아니게 되어, 비교 실험(Q5)을 중단했습니다.

## 폴더 구조

```
docs/
├── 00-pipeline-design.md   상세 설계
├── 01-research-plan.md     연구 계획서
├── features/               기능 설계서 (사람 작성)
├── plans/                  구현 계획과 결정 기록 (메인 세션 작성)
├── insights/               프롬프트 패턴 카드와 예시
└── journal/                연구 일지
research/
├── REPORT.md               정리 보고서
├── pipeline-test-report.docx  시험 보고서
├── hooks/                  에이전트 호출 실시간 기록
├── tools/                  수집·채점·비식별화 스크립트
├── config/                 단가표 등 설정
├── eval/                   숨긴 평가 테스트 (기능별)
├── logs/                   실시간 원본 로그 (비공개)
└── runs/                   실행별 결과
```
